# 语言、框架规范与 GitHub 脚手架来源

观察日期：2026-10-24。本轮选定 10 类语言、每类 3 个不同 GitHub 项目，共 30 个脚手架、模板或生成的完整应用起点，实际读取 36 份构建及依赖管理文件。不能用教程、工具库或框架源码根构建文件代替三个脚手架；Drogon 计入的是其生成项目的 CMake 模板。

## 读取与扩展规则

- 先读取 [general.std](general.std)，再读取语言入口和实际采用的框架规范，并叠加相关专项规范。
- 语言入口使用 `std/{语言}/{语言}.std`，框架使用 `std/{语言}/framework/{框架}/{框架}.std`；跨语言框架复用一份正文。
- 编译插件、运行时、测试依赖、BOM 管理、模板条件和版本目录分别识别；出现在 BOM 中不代表应用已启用。
- 历史模板及 RC/preview 依赖只作为发现证据；不把模板版本、目录或配置作为新项目默认标准。
- 标准只约束项目实际采用的组件，不触发安装、升级、clone 或复制第三方代码；Flutter 当前兼含 Dart 基础规则，尚无独立 dart.std。
